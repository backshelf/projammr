# Security policy

## Supported versions

Security fixes are made for the latest minor release. Older releases do not receive fixes; upgrade to the latest
minor to get them.

## Reporting a vulnerability

Please report vulnerabilities privately. Do not open a public issue, pull request or discussion for one.

Use GitHub's private vulnerability reporting: open the repository's **Security** tab, choose **Advisories**, and
select **Report a vulnerability**. Only the maintainer can see the report.

Please include:

- the version affected (the release tag, or the commit if you built from source) and how you installed it
  (published images, built from source, or the dit download);
- what the vulnerability is and what an attacker gains from it;
- the steps to reproduce it, or a proof of concept, and the request or file involved;
- any logs or output that show it;
- whether you have shared the details with anyone else.

## What to expect

- An acknowledgement within 7 days of your report.
- Follow-up questions if the report needs more detail.
- Updates when the issue is confirmed, when a fix is in progress and when a release contains it.
- Credit in the advisory once the fix is released, if you want it.

Please give the maintainer reasonable time to release a fix before you disclose the issue publicly.
