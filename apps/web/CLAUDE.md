# apps/web

Projammr's public website: the marketing pages and the docs, built as a fully static site with Astro and Starlight
and hosted on Cloudflare Pages, apart from the self-hosted stack. It pitches the finished product (open source under
AGPL-3.0, self-hostable, plus paid hosting) and documents the app, the API, self-hosting and contributing. The
design world is the app's own (`DESIGN.md`); the page accent comes from the four covers the site borrows. Full
reference: `docs/agents/web.md`.

## Where things go

- Marketing pages: `src/pages/*.astro`, each rendered in `src/layouts/SiteLayout.astro`. Shared chrome in
  `src/components/chrome/`, the theme script and toggle in `src/components/theme/`.
- Docs: MDX under `src/content/docs/docs/<section>/`, served at `/docs/<section>/…`. Sections: `guide` (using the
  web app), `collaboration`, `admin` (running an instance's users from the app), `api`,
  `self-hosting`, `contributing`. Each section is one flat directory with its own sidebar group in
  `astro.config.ts`; Starlight labels a nested directory with its raw name and cannot relabel it, so never nest.
- API reference: generated by `starlight-openapi` from the committed `openapi/api.json` and `openapi/auth.json`.
  Never edit those by hand; `bun run typegen` rewrites them from the server.
- Starlight overrides: `src/components/starlight/` (brand, primary links, theme). Starlight's palette is mapped
  onto the spine in `src/styles/docs.css`; marketing pages load `src/styles/site.css`.
- Site facts (domain, repository, licence, dit's download): `src/site.ts`. Header and footer links: `src/nav.ts`.
- Screenshots: captured by `scripts/screenshots/` (the list is `manifest.ts`) from the seeded demo catalogue
  (`packages/demo`), never from real data, into `src/assets/screenshots/<id>.<light|dark>.<desktop|phone>.webp`,
  shown with `<Screenshot id alt />` from `@/components/Screenshot.astro`.
- Covers: `src/assets/covers/` are copies of the project's own design assets in `fixtures/covers/`, with the accent
  the server extracts from each in `src/data/covers.ts`. A raster the site ships is a cover or a screenshot; add
  no other kind without recording where it came from here.
- A React component rendered on a page is imported from `@workspace/ui` and used without a `client:` directive, so it
  ships as HTML only. Add its file to the `@source` lines in `site.css` or its classes compile to nothing.

## Writing docs

- Frontmatter: `title`, a one-sentence `description`, and `sidebar.order` for position within the section.
- Every statement is checked against the source or `docs/agents/<area>.md`. Document what the code does today;
  never a planned feature, a figure nobody measured, or a user who does not exist.
- The only music named anywhere on the site is the demo catalogue's invented songs, sets and people
  (`packages/demo`). Never a title, file name, sample path or collaborator from the owner's own unreleased music,
  including examples lifted from `docs/agents/` or `PRODUCT.md`, which name some.
- Second person, present tense, sentence-case headings, the product's own vocabulary (sessions, saves, bounces,
  versions, renders, collections). Australian/British spelling (colour, catalogue, organise), as the codebase uses.
- Components: Starlight's `Aside`, `Steps`, `Tabs`/`TabItem`, `FileTree`, `LinkCard` from
  `@astrojs/starlight/components`, and `<Screenshot>`. No `Card`/`CardGrid`: DESIGN.md rejects cards.
- Internal links are absolute with a trailing slash (`/docs/self-hosting/backups/`). The link validator fails the
  build on a broken one.
- Commands and config are copy-pasteable and carry a language tag.

## Commands

```bash
bun run dev          # astro dev on WEB_PORT (default 4321)
bun run build        # static build to dist/; fails on a broken docs link or a marketing page over the JS budget
bun run typecheck    # astro sync, then tsc 7.1 with the .astro content mapper (scripts/typecheck.ts)
bun run test         # bun test: spec drift, JS budget, screenshots captured
bun run typegen      # rewrite openapi/*.json from the server's in-process spec
```

## Gotchas

- TypeScript here is a pinned 7.1 nightly with `@astrojs/ts-content-mapper`, because `astro check` does not run on
  TS 7. `scripts/typecheck.ts` skips diagnostics inside `node_modules` the way `skipLibCheck` would; a diagnostic in
  this package's own files still fails.
- `satteri` and `@astrojs/markdown-satteri` are direct dependencies and stay external to the prerender build
  (`astro.config.ts`): bundled, their native binding cannot be found under Bun's isolated install.
- Marketing pages get Tailwind's preflight through `site.css`; the docs do not, because Starlight keeps its own reset.
- The theme is one stored choice (`projammr-theme`) driving both `.dark` (the token layer) and `data-theme`
  (Starlight). Never add a second theme script.
- A marketing page may ship at most `MARKETING_JS_BUDGET_BYTES` of script (`src/integrations/js-budget.ts`): the
  inline theme script and Astro's prefetch. Nothing hydrates.
- `test/screenshots.test.ts` fails while any `<Screenshot>` id is uncaptured; capture it rather than removing the
  reference.
