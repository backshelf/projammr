Run these checks yourself before you open a pull request; a change is ready when they are all clean. GitHub Actions
runs the build and test suites on every pull request to `master`, and runs the remaining static, end-to-end and
packaging checks for every release.

## The checks

| Command                          | What it checks                                                                                 |
| -------------------------------- | ---------------------------------------------------------------------------------------------- |
| `bun run typecheck`              | Regenerates the API types, then type-checks every workspace. **The check that matters most**   |
| `bun run lint`                   | ESLint and `cargo clippy` across every workspace                                               |
| `bun run format`                 | Formats everything with Prettier (and sorts Tailwind classes) and `cargo fmt`                  |
| `bun run knip`                   | Unused files, exports, types and dependencies across workspaces (run after `typecheck`)        |
| `bun run version:check`          | Every workspace manifest, Rust crate and lockfile carries the root `package.json` version      |
| `bun run test`                   | Every test suite except the API's (includes `cargo test` in `packages/dsp` and `packages/dit`) |
| `cd apps/server && bun run test` | The API's suite, which needs a database                                                        |
| `bun run build`                  | Builds every workspace: the WASM crates first, then the API types, then the apps               |
| `bun run audit`                  | `bun audit` for known vulnerabilities at the `high` level                                      |

All of them run from the root of the repository.

### Typecheck

`bun run typecheck` runs `bun run typegen` first, so the web app and shared packages are always checked against the
API as it is on your branch. A route change that breaks a caller fails here.

### Lint and format

Locally, every lint rule is a warning, so `bun run lint` never fails; CI runs it with `--max-warnings 0`, where any
warning fails the job. Read its output and leave none behind.

`bun run format` rewrites files in place. CI runs it and fails if anything changed, so format before you commit.
Prettier is configured once, in `.prettierrc` at the root, with the Tailwind plugin sorting class names.

### Tests

Tests are `bun test` everywhere, in `*.test.ts` files next to the code they cover, importing from `bun:test`.
`@workspace/test` holds the shared helpers: global and environment stubs, fake timers, and polling.

`bun run test` at the root runs every suite except the API's. The API's suite runs on its own, because it needs a
PostgreSQL server:

```bash
cd apps/server
bun run test                          # the whole suite
bun test src/routes/notes.test.ts     # one file
bun test -t "returns 403"             # tests whose name matches
```

It reads `DATABASE_URL` from `apps/server/.env`. Some of its tests create and drop databases of their own, so the
role in that URL needs permission to create databases, and some run ffmpeg on real audio, so ffmpeg has to be
installed. The suite calls the app in process and never listens on a port, so it can run while `bun run dev` is up.

### Build

`bun run build` builds everything the way a release would. It is the only check that catches some mistakes: a
server-only module imported into the browser in the web app, or a broken bundle in the dit panel. For this site, the
build also validates every link between docs pages and fails on a broken one.

## What CI runs

In `.github/workflows/ci.yml`, pull requests to `master` run `test-build`. Release tags
(`.github/workflows/release.yml`) run every job below, plus the multi-arch Docker image build and smoke check, and the
signed macOS dit package (`dit-app-package.yml`).

| Job          | When           | What it runs                                                                                       |
| ------------ | -------------- | -------------------------------------------------------------------------------------------------- |
| `test-build` | PRs & releases | `bun run build`, `bun run test:ci` (every non-server suite), and the server suite on PostgreSQL 17 |
| `lint`       | Releases       | `bun run lint:ci` (`--max-warnings 0`), no Jira keys in source, and `bun run version:check`        |
| `format`     | Releases       | `bun run format`, then fails if any file changed                                                   |
| `typecheck`  | Releases       | `bun run typecheck`, `packages/api/src/enums.ts` drift check, and `bun run knip`                   |
| `audit`      | Releases       | `bun run audit`                                                                                    |

<Aside>
  If `enums.ts` fails the `typecheck` job (or `apps/web/test/openapi.test.ts`
  fails in `test-build`), a route or a database enum changed without the
  generated files being committed. Run `bun run typegen` and commit what it
  writes.
</Aside>
