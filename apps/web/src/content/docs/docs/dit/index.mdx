**dit** is the companion app that runs on the Mac you make music on. While **Projammr** is your self-hosted web hub —
the catalogue, listening room, waveform comments, notes and lyrics — **dit** sits beside your DAW on disk, recording
every save of a set into a content-addressed `.dit/` repository inside the project folder and syncing that history, your
commits and your bounces to your Projammr instance.

## How dit and Projammr work together

- **dit lives on your studio Mac.** It watches tracked project folders for saves, detects new audio bounces, tracks time
  spent in a set, writes commits and branches, and restores earlier commits back to disk as new set files.
- **Projammr is the hub.** When dit pushes, your saves, diffs, commits, time spans, samples (when enabled) and accepted
  bounces appear on your Projammr server, where you and your collaborators can inspect changes, listen to versions, leave
  timestamped comments and open or restore sets from any tracked Mac.
- **Everything works locally first.** Saves, commits, diffs and local branches are stored in `.dit/` inside each project
  folder. If your Projammr server is offline or you are working away from home, dit keeps recording locally and pushes
  when the server is reachable again.

## Requirements

- **Apple silicon Mac (`arm64`)** running **macOS 14 or later**.
- A running **Projammr instance** to sign in to and push to (local saves and CLI commands work offline before you push).
- **Ableton Live** for automatic set watching, Live's `dit` control-surface script and the optional Ableton Live
  extension.

## DAW module architecture

Inside dit, the core repository format — content-addressed objects, save logs, commits, branches, diffs, time tracking
and pushing — is DAW-agnostic. Each supported DAW is implemented as a separate module responsible for:

- recognising a project folder and its managed subfolders;
- decoding and re-encoding set files;
- splitting a set into tracks and sections and masking volatile view state;
- extracting metadata (tempo, key, time signature, tracks, devices, plugins, clips, scenes and sample references); and
- locating the DAW's own backup copies.

**Ableton Live** (`.als` sets inside Live project folders, including `Samples/` and `Backup/`) is the DAW module
implemented today.
